# 新版说明：拍照签到、地图选点与常用坐标库

基于 TimePineapple/chaoxing-sign main 的改造，保留原项目身份认证、账号管理、扫码队列、事件流、动态二维码、摄像头配置、课程、设置和历史记录。改进版源码发布于 https://github.com/st-cx/chaoxing-sign ，原作者仓库保持不变。

## 使用方法

1. 首页直接点击常用地点卡片选用，右侧“当前使用”始终展示本次位置；刷新后自动恢复上次选择。
2. 点“＋ 添加地点”默认打开地图。输入城市、学校或地址，搜索后点选结果；也可直接拖动、缩放地图，点击具体楼栋选点。
3. 填写名称后点“保存并使用”，窗口关闭并立即切换到新地点。只保存时用“保存到坐标库”。
4. “粘贴坐标”是备用入口，会自动识别“经度,纬度”；此时需要确认坐标来源。百度为 BD-09，GPS 为 WGS-84；高德/腾讯的 GCJ-02 不可直接作为这两种坐标保存。
5. 地图搜索默认使用 Photon / OpenStreetMap，无需密钥；如配置 BAIDU_MAP_SERVER_AK，则使用百度地理编码。地图瓦片需联网，搜索服务可能限流或不可用，仍可粘贴坐标。自建 Photon 可通过 MAP_PHOTON_ENDPOINT 配置。
6. 首页、扫码弹窗和位置签到共用同一地点选择，提交时读取坐标快照；账号默认设置仍在“设置”中独立保存。
7. “管理”中保留搜索、编辑、删除及导入/导出。

坐标库和上次选择按本站用户隔离，保存在当前浏览器中。更换用户时载入该用户自己的条目和选择；退出清除内存状态。兼容第一版存储，没有保存过选择时使用浏览器定位。版本 1 JSON 导出不携带运行选择，可跨浏览器导入；导入先校验并去重合并，不覆盖原条目。损坏存储停止写入，最大 200 条。

## 拍照与其他签到

账号卡片点击“拍照签到”即可查看该账号正在进行的拍照活动。选择活动后可选图片、拖入图片，或在支持的手机浏览器中通过“拍摄照片”调用系统相机；支持 JPG/PNG/WebP，最大 5 MB。先本地预览，点击“上传照片并签到”后才上传到该账号的超星云盘并提交。切换活动或关闭窗口会清除照片；失败保留输入方便重试。

“其他签到”统一提供普通、位置、签到码、手势及原扫码入口。服务端重新获取活动详情、验证账号归属及课程，不接受客户端伪造签到类型；避免重复提交。原自动签到和云盘 0.jpg/0.png 的照片查找逻辑仍保留，但不再使用代码中固定的公共云盘凭证。

参考 MIT 开源项目的照片上传协议并适配现有登录会话，来源及许可证见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。照片不写服务器临时文件，不保存到浏览器坐标库；未提交时不会上传。

## 结构约定

`utils/locationLibrary.ts` 负责纯数据校验、导入、粘贴解析与去重；`stores/locations.ts` 是坐标库和选择 ID 的唯一持有者。`plugins/locationLibrary.client.ts` 随本站用户切换初始化；组件读同一 Store。

数据流：本地条目 → selectedId → runtimeLocation 坐标快照 → 原有扫码/手动位置请求 → 服务端坐标处理。账号默认设置与运行时选择独立，编辑草稿不会直接修改 Store。

请求仍采用原有 `location` 对象，新增可选 `coordinateSystem: 'wgs84' | 'bd09'`。旧客户端不传该字段仍按 WGS-84 处理。服务端校验枚举，扫码入队保留字段，百度逆地理缓存按坐标系隔离。原有坐标处理函数移动到共享纯函数文件，服务端原入口继续导出，调用者不必迁移路径。

## 交互修复

- 设置草稿深拷贝，取消不落库，重置不修改共享默认值；保存失败保留输入、业务错误不显示成功。
- 防止重复保存/移除/课程操作；过期账号保留重新登录、续登和设置入口，仍不可批量选中。
- 弹窗移出账号卡片点击容器，避免弹窗操作改变账号勾选；卡片支持键盘操作。
- 全选状态由可用账号实时推导，排除失效账号；同步账号保留既有选择；无选择时批量按钮禁用。
- 增加账号搜索、状态筛选与课程入口，修复刷新课程详情页后的空账号状态。
- 课程活动请求忽略晚到的旧课程结果；关闭扫码窗口后不会继续发送仍在等待定位的请求。
- 消息 API 延迟创建，避免 Store 初始化或服务端渲染阶段创建浏览器弹层。

## 运行与验证

完整应用仍需要原项目的 PostgreSQL、本站账号和环境配置；地点搜索默认无需密钥；位置签到的服务端地址解析仍需配置 `BAIDU_MAP_SERVER_AK`。数据库模型、注册开关和原扫码队列不变；新增手动签到接口执行独立的账号归属验证。自动化与示例预览不调用真实签到。部署后已验证已有账号保留、活动查询与在线地点搜索；尚未验证真实照片上传、真实签到及手机相机全流程。

在本机使用 Node 20.19.5 + pnpm 9.15.9 验证。Node 24 对该项目旧 Nuxt 依赖存在加载兼容问题。`.npmrc` 缩短了本项目的 pnpm 依赖路径，防止 Windows 深目录加载失败；未更改全局设置。

```shell
pnpm install --frozen-lockfile
pnpm test:ui
pnpm build
```

独立预览复用实际 Vue 组件，只注入示例账号、存储身份和请求替身，明确标注“交互预览 · 示例数据”。预览中的地址搜索也返回明确标注的示例地点；地图瓦片在线加载。它不会登录、同步真实账号或调用签到接口，不可用其成功提示推断正式服务已验证。

```shell
pnpm demo         # 开发预览 127.0.0.1:4173
pnpm demo:build   # 生成 .preview
pnpm demo:start   # 内置静态服务器 127.0.0.1:4176
```

交付包包含已构建 `.preview`，安装 Node 后可直接运行 `start-preview.cmd`，不用数据库或安装项目依赖。正式应用按原 README 配置，不要把预览作为真实服务部署。

GitHub 源码仓库不跟踪生成的 `.preview`。从 GitHub 克隆时，先安装依赖并运行 `pnpm demo:build`，再启动预览。
